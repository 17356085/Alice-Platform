### 4. 测试策略与风险考量

1.  **稳定性保障**：
    - **选择器策略**：优先使用`data-testid`，其次考虑稳定且唯一的CSS类名路径（如`.ant-table-tbody .ant-table-row:first-child td:nth-child(2)`）。坚决避免依赖动态生成的类名（如`.css-1a2b3c`）。
    - **异步处理**：所有异步操作（点击查询/翻页/批量操作）后，**必须等待**`Loading`状态结束或关键网络请求响应完成，再执行下一步断言。
    - **显式等待**：在执行关键操作（如点击“同意”）前，断言该按钮是可点击状态，避免因前置条件失败导致无效点击。

2.  **数据隔离与冲突**：
    - 并发测试时，不同用例应操作不同的数据ID或使用不同的测试会话。避免用例A修改了用例B期望查询到的数据。

3.  **环境依赖与模拟**：
    - **API Mock**：使用Playwright的`page.route`或MSW，在单元/组件测试阶段拦截并模拟API响应，实现测试与后端解耦。
    - **网络模拟**：使用`page.route`模拟网络延迟、断网、服务器错误(500)等场景，验证前端的容错与提示。

4.  **未覆盖的潜在风险场景**：
    - **输入安全**：在关键词输入框中注入XSS/SQL片段，验证前端是否转义或后端是否过滤。
    - **防重复提交**：在“同意”按钮点击后、Loading期间，再次快速点击该按钮，应无响应或按钮自动禁用。
    - **权限边界**：模拟不同权限的用户登录，验证其能看到的筛选项、操作按钮是否符合权限策略。
    - **浏览器兼容性**：关键功能在主要浏览器（Chrome, Firefox）上进行冒烟测试。
