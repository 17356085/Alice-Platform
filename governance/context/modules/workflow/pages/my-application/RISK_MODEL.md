# RISK_MODEL：workflow模块 - my-application页面风险矩阵

## 1. 页面上下文假设 (PAGE_CONTEXT)
**页面功能**：工作流模块的“我的申请”页面，是用户发起、查看、管理个人工作流申请（如请假、报销、合同审批等）的核心操作中心。
**核心业务流程**：
- 1.1 **提交新申请**：选择申请类型 → 填写动态表单 → 预览 → 提交。
- 1.2 **查看与跟踪**：查看申请列表（支持筛选、搜索）、申请详情、流转状态、审批意见、历史记录。
- 1.3 **操作与管理**：对草稿进行编辑/删除、对被驳回的申请进行修改/重新提交、撤回已提交但未审批的申请。
**技术复杂度关键点**：
- 与工作流引擎深度集成，涉及动态表单渲染、复杂状态机流转。
- 实时或准实时的审批状态同步。
- 多种申请类型带来不同的表单字段与校验规则。
- 可能涉及附件上传、电子签名等组件。

## 3. 风险等级统计
- **P0 (核心流程+高复杂度)**: **6** 例
  - *占比*：46.2% (6/13)
  - *说明*：风险集中。所有与**申请提交、编辑、重新提交、撤回**的核心业务写操作及关键数据交互（如附件、必填校验）均属最高风险，需投入最多测试资源，确保主路径零缺陷。
- **P1 (常规功能)**: **5** 例
  - *占比*：38.5% (5/13)
  - *说明*：主要覆盖信息展示（列表、详情、搜索）和基础管理操作（删除草稿、网络异常处理）。功能重要，但业务逻辑相对直接。
- **P2 (边缘场景)**: **2** 例
  - *占比*：15.4% (2/13)
  - *说明*：并发冲突、大文件上传等低频或边界场景。在核心流程稳定后进行补充验证。

## 4. 测试策略建议
1.  **P0 用例**：必须进行端到端自动化回归测试，并覆盖主要主流浏览器和设备。上线前需进行手工探索性测试。
2.  **P1 用例**：建议实现UI自动化测试，作为版本发布的验收标准之一。
3.  **P2 用例**：可在主要版本或性能测试中纳入，无需每次发布都全量执行。
4.  **重点回归**：当**工作流引擎、表单组件、状态管理模块**发生变更时，必须对所有P0用例进行全量回归测试。
