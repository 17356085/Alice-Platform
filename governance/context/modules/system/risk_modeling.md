# 系统模块测试风险模型

## 1. 风险评分矩阵 (业务影响 × 技术复杂度)

| 业务影响 \ 技术复杂度 | 低 (1) | 中 (2) | 高 (3) |
| :--- | :--- | :--- | :--- |
| **高 (3)** | P1 | P1 | **P0** |
| **中 (2)** | P2 | P1 | P1 |
| **低 (1)** | P2 | P2 | P2 |

**等级定义:**
*   **P0 (阻塞性):** 核心业务流程断裂或存在重大问题，必须立即修复才能上线。
*   **P1 (高优):** 影响主要功能或用户体验，应在当前迭代内修复。
*   **P2 (常规/低优):** 边缘场景、UI 小缺陷、非关键路径问题，可后续修复。

## 2. 用例风险评估

### 2.1 核心流程 (P0等级)
*   **业务影响:** 高 (3) - 直接影响用户完成关键任务。
*   **技术复杂度:** 高 (3) - 涉及多系统交互、复杂状态管理或外部依赖。
*   **用户故事:** 作为[角色]，我希望[执行核心业务操作]，以便[完成核心目标]。
*   **风险等级:** **P0**

### 2.2 常规功能 (P1等级)
*   **业务影响:** 高 (3) - 影响核心用户流程，但拥有备用方案或影响范围有限。
*   **技术复杂度:** 中 (2) - 前端逻辑清晰，或后端API调用较简单。
*   **用户故事:** 作为[角色]，我希望[进行常规功能操作]，以便[提升效率]。
*   **风险等级:** **P1**

### 2.3 边缘场景 (P2等级)
*   **业务影响:** 低 (1) - 极少发生或只在特定条件下触发。
*   **技术复杂度:** 高 (3) - 复现困难，涉及极端值或异常处理逻辑。
*   **用户故事:** 作为[角色]，当[操作/条件]时，系统应[表现正常]。
*   **风险等级:** **P2**
