#### **2. 测试用例（按优先级 P0 -> P2 排列）**

##### **P0（核心功能 - 阻塞性问题）**

*   **用例ID:** TC-001
*   **测试标题:** 验证管理员成功创建一个新用户
*   **优先级:** P0
*   **前置条件:**
    *   用户已使用管理员权限账号登录系统。
    *   用户管理页面正常显示。
*   **测试步骤:**
    1.  导航至“用户管理”页面。
    2.  点击“新增用户”按钮。
    3.  在弹出表单中填写必填字段（用户名、真实姓名、邮箱、初始密码）。
    4.  从“角色”下拉框选择一个角色（如：普通用户）。
    5.  点击“保存”或“提交”按钮。
*   **预期结果:**
    *   系统提示“用户创建成功”。
    *   用户列表页出现新创建的用户记录。
    *   新用户可以使用其用户名和密码成功登录系统，并拥有被分配角色的权限。

*   **用例ID:** TC-002
*   **测试标题:** 验证不同角色用户访问权限的差异性
*   **优先级:** P0
*   **前置条件:**
    *   存在“管理员”角色和“普通用户”角色。
    *   管理员角色拥有“系统配置”查看/编辑权限；普通用户角色没有此权限。
*   **测试步骤:**
    1.  以“管理员”角色登录，确认可以访问“系统配置”页面并进行修改。
    2.  注销管理员账号。
    3.  以“普通用户”角色登录系统。
    4.  直接尝试通过URL或菜单导航至“系统配置”页面。
*   **预期结果:**
    *   普通用户无法看到“系统配置”菜单项（如果菜单基于角色动态渲染）。
    *   普通用户直接访问URL后，被重定向到首页或显示“无权限访问”的错误提示。

##### **P1（重要功能 - 不影响核心流程，但影响体验）**

*   **用例ID:** TC-003
*   **测试标题:** 验证系统全局配置的修改立即生效
*   **优先级:** P1
*   **前置条件:**
    *   管理员已登录。
    *   系统配置页面包含“站点名称”字段。
*   **测试步骤:**
    1.  导航至“系统配置”页面。
    2.  修改“站点名称”为新的值（例如：从“开发站”改为“生产站”）。
    3.  点击“保存设置”。
    4.  刷新所有浏览器标签页或重新登录。
    5.  检查浏览器标题栏、页面顶部LOGO区域或系统名称显示区。
*   **预期结果:**
    *   保存后提示“配置更新成功”。
    *   系统所有界面上显示的站点名称都更新为“生产站”。

*   **用例ID:** TC-004
*   **测试标题:** 验证审计日志能正确记录用户操作
*   **优先级:** P1
*   **前置条件:**
    *   审计日志模块已启用。
    *   存在至少一个活跃用户（user_a）。
*   **测试步骤:**
    1.  使用 user_a 登录系统。
    2.  在“用户管理”页面，将一个用户“禁用”。
    3.  注销 user_a 账号。
    4.  使用管理员账号登录，导航至“审计日志”页面。
    5.  使用过滤器搜索 user_a 的用户名或操作类型“禁用用户”。
*   **预期结果:**
    *   审计日志列表中能搜索到一条记录。
    *   记录包含以下信息：操作者（user_a）、操作时间、操作IP、操作内容（禁用了哪个用户）、操作状态（成功）。

*   **用例ID:** TC-006
*   **测试标题:** 验证审计日志长时间段内搜索的响应性能

    2.  导航至“审计日志”页面。
