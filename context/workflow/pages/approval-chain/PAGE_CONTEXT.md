# TEST_DESIGN.md

## 1. 测试目标与范围
本文档旨在为 `workflow` 模块的 `approval-chain` 页面设计一套完整的测试方案，以验证其核心功能、数据准确性、交互逻辑及系统健壮性。
**测试范围**覆盖页面三大核心模块：**数据检索**、**数据操作**、**数据展示与分页**。

## 2. 页面功能模块分析与测试设计
基于页面结构分析，将测试设计分为以下模块，每个模块均包含具体的测试场景和验证点。

### 2.1 数据检索模块测试设计
此模块负责数据的查询与过滤，主要测试元素为**搜索输入框**、**状态下拉框**以及相关的**搜索/重置按钮**。

| 测试子模块 | 测试用例ID | 测试场景描述 | 测试步骤 | 预期结果与验证点 |
| :--- | :--- | :--- | :--- | :--- |
| **关键词搜索** | TC-SEARCH-01 | 使用有效关键词搜索 | 1. 在搜索框输入已存在的审批链名称或编码。<br>2. 点击搜索按钮或按回车。 | 列表精确刷新，仅显示匹配该关键词的数据条目。 |
| | TC-SEARCH-02 | 搜索无匹配结果 | 1. 在搜索框输入不存在的字符串（如 `test123xyz`）。<br>2. 执行搜索。 | 列表清空，显示“无数据”或类似友好提示。 |
| | TC-SEARCH-03 | 清空搜索条件 | 1. 执行搜索后，清空搜索框。<br>2. 再次执行搜索或触发默认加载。 | 列表恢复至搜索前的状态（如显示全部或状态筛选后的结果）。 |
| | TC-SEARCH-05 | 搜索特殊字符 | 1. 在搜索框输入特殊字符（如 `!@#$%^&*`）。<br>2. 执行搜索。 | 系统不报错，界面正常响应。列表因无匹配而显示为空或“无数据”。 |
| | TC-SEARCH-06 | 搜索超长字符串 | 1. 在搜索框输入超过输入框长度限制的字符串。<br>2. 执行搜索。 | 输入框能正常处理（截断或滚动显示），搜索功能正常执行，无页面崩溃。 |
| **状态筛选** | TC-SEARCH-04 | 按状态筛选列表 | 1. 点击状态下拉框。<br>2. 分别选择“全部”、“启用”、“禁用”。 | 列表根据所选状态准确刷新，仅显示对应状态的数据。 |
| | TC-FILTER-02 | 仅状态筛选 | 1. 保持搜索框为空。<br>2. 选择特定状态（如“启用”）。 | 列表仅显示该状态的所有数据。 |
| **组合与重置** | TC-FILTER-01 | 组合查询（搜索+状态） | 1. 输入关键词进行搜索。<br>2. 同时切换状态筛选下拉框。 | 两个条件叠加生效，列表显示同时满足关键词和状态的数据。 |
| | TC-FILTER-03 | 重置所有筛选条件 | 1. 设置好搜索关键词和状态筛选。<br>2. 点击“重置”按钮（若存在）。 | 搜索框清空，状态下拉框恢复为“全部”，列表显示全部数据。 |

### 2.2 数据操作模块测试设计
此模块负责数据的增删改及状态管理，主要测试元素为**新建、编辑、删除、启用/停用按钮**及相关**弹窗**。

| 测试子模块 | 测试用例ID | 测试场景描述 | 测试步骤 | 预期结果与验证点 |
| :--- | :--- | :--- | :--- | :--- |
| **新建** | TC-LIST-ADD-01 | 新建审批链 | 1. 点击“新建”按钮。 | 成功跳转至新建页面或弹出新建对话框，界面元素（如名称、节点配置）加载正常。 |
| **编辑** | TC-LIST-EDIT-01 | 编辑已有审批链 | 1. 在列表中点击一条数据的“编辑”按钮。 | 成功跳转至编辑页面或弹出编辑对话框，且该条数据的现有信息（名称、配置等）被正确预填充。 |
| **删除** | TC-LIST-DELETE-01 | 触发删除操作 | 1. 在列表中点击一条数据的“删除”按钮。 | 弹出二次确认对话框，提示“确定删除吗？”。 |
| | TC-LIST-DELETE-02 | 确认删除 | 1. 在确认对话框中点击“确定”。 | 显示“删除成功”提示，该数据从列表中移除，列表自动刷新。 |
| | TC-LIST-DELETE-03 | 取消删除 | 1. 在删除确认框中点击“取消”或关闭。 | 对话框关闭，数据保留在列表中，无任何变化。 |
| | TC-LIST-DELETE-04 | 防止重复删除操作 | 1. 快速连续多次点击同一数据的“删除”按钮。 | 只弹出一次删除确认对话框，防止重复操作。 |
| | TC-LIST-DELETE-05 | 删除后分页更新 | 1. 删除一条数据。<br>2. 查看剩余数据和分页信息。 | 列表数据条数减少，分页总数（“共X条”）相应更新。 |
| **状态切换** | TC-LIST-TOGGLE-01 | 停用启用状态的审批链 | 1. 点击一条“启用”状态数据的“停用”按钮。 | 提示操作成功，该条数据状态变为“禁用”，操作按钮文字变为“启用”。 |
| | TC-LIST-TOGGLE-02 | 启用禁用状态的审批链 | 1. 点击一条“禁用”状态数据的“启用”按钮。 | 提示操作成功，该条数据状态变为“启用”，操作按钮文字变为“停用”。 |
| | TC-LIST-TOGGLE-03 | 操作中防止重复提交 | 1. 点击“启用/停用”按钮，在接口响应期间。<br>2. 尝试再次点击该按钮或进行其他操作。 | 按钮应显示加载状态（如转圈）或暂时禁用，直至操作完成。 |

### 2.3 数据展示与分页模块测试设计
此模块负责数据的呈现与分页浏览，主要测试元素为**数据表格**和**分页控件**。

| 测试子模块 | 测试用例ID | 测试场景描述 | 测试步骤 | 预期结果与验证点 |
| :--- | :--- | :--- | :--- | :--- |
| **数据展示** | TC-LIST-VIEW-01 | 验证列表数据准确性 | 1. 检查列表中一条数据的各列（编码、名称、状态、节点数、更新时间等）。 | 各列数据展示完整、准确，与后台数据或业务规则一致。 |
| | TC-LIST-VIEW-02 | 数据空状态展示 | 1. 通过搜索/筛选，使列表结果为空。 | 列表区域显示友好的“暂无数据”或类似提示，而非空白或错误。 |
| **分页功能** | TC-PAGINATE-01 | 翻页（上一页/下一页） | 1. 数据存在多页时，点击“下一页”、“上一页”。 | 列表数据随页码切换正确更新，分页信息（如“2/5页”）同步变化。 |
| | TC-PAGINATE-02 | 切换每页显示条数 | 1. 点击“每页条数”下拉框，从10条切换为20条。 | 列表立即刷新，每页显示20条数据，总页数相应减少。 |
| | TC-PAGINATE-03 | 页码跳转 | 1. 在“跳至”输入框输入一个有效页码（如3）。<br>2. 点击“跳至”或按回车。 | 列表跳转到第3页，显示对应数据。 |
| | TC-PAGINATE-04 | 无效页码跳转 | 1. 在“跳至”输入框输入无效页码（如0、负数、大于总页数的数、非数字）。<br>2. 尝试跳转。 | 系统应阻止跳转，输入框恢复原值或清空，或给出提示。 |

## 3. 测试数据设计
为支持上述测试场景，需在测试环境中预先准备或动态构造以下数据：

| 数据类别 | 设计要点 | 用途示例 |
| :--- | :--- | :--- |
| **基础审批链数据** | 包含多种名称格式：<br>1. **标准名称**：中文（“采购审批链”）、英文（“HR-Approval”）。<br>2. **边界名称**：含空格（“财务 审批”）、特殊字符（“IT-审批_v1.0”）。<br>3. **异常名称**：超长字符串（50+字符）。 | 用于测试搜索、列表显示、新建/编辑功能的输入处理与显示。 |
| **状态分布数据** | 确保存在“启用”和“禁用”两种状态的数据，且数量足够（如各至少2条）。 | 用于测试状态筛选、启用/停用操作及其结果验证。 |
| **分页压力数据** | 创建足够数量的审批链记录（建议30条以上），确保列表能产生至少2-3页。 | 用于全面测试翻页、切换每页条数、页码跳转等分页功能。 |
| **操作影响数据** | 1. 专门用于测试删除操作的数据。<br>2. 专门用于测试状态切换的数据。 | 用于验证操作后的列表刷新、分页更新等联动效应。 |

## 4. 核心综合验证点清单
在执行所有测试用例时，需贯穿验证以下非功能性要点：
1.  **功能与交互完整性**：
    - 所有按钮、输入框、下拉框、分页控件均可点击并触发预期响应。
    - 关键操作（删除、启用/停用）有明确的二次确认流程。
2.  **数据一致性**：
    - 列表数据、搜索结果、筛选结果与后端接口返回的数据保持一致。
    - 执行增、删、改、状态切换操作后，列表数据、分页总数（“共X条”）实时同步更新。
3.  **异步操作与反馈**：
    - 在数据加载、删除、状态切换等异步操作期间，应有明确的加载状态提示（如加载动画、按钮禁用），防止用户重复提交。
    - 操作完成后，应有明确的成功/失败提示（如Toast消息）。
4.  **异常处理与容错**：
    - 列表无数据时，展示友好提示而非空白页面。
    - 输入非法或极端数据（特殊字符、超长字符串）时，系统不崩溃，能给出合理提示或正常处理。
    - 分页组件在首页（“上一页”禁用）、末页（“下一页”禁用）、单页等边界状态下，按钮状态正确。
5.  **流程联动**：
    - 验证“搜索/筛选”与“分页”的联动（如搜索后分页重置）。
    - 验证“数据操作”与“列表/分页刷新”的联动（如删除后列表和分页同步变化）。
