### 2. 详细测试用例

#### **TC-01: 页面加载与默认数据展示**
*   **ID:** TC-01
*   **标题:** 页面加载与默认数据展示
*   **优先级:** P0
*   **前置条件:**
    1.  测试环境数据库中存在不少于100条审批历史记录。
    2.  用户已登录并拥有访问“审批历史”页面的权限。
*   **测试步骤:**
    1.  通过导航菜单进入“审批历史”页面。
    2.  观察页面加载过程及加载完成后的初始状态。
*   **预期结果:**
    1.  **页面加载**：页面无JavaScript控制台错误。所有元素（`#timeRangeSelector`, `#statusFilter`, `#typeFilter`, `#initiatorSearch`, `#searchBtn`, `#resetBtn`, `#approvalListTable`, `#pagination`）均可见且处于默认状态（如：时间范围为默认值，状态/类型筛选器为空/全选）。
    2.  **加载状态**：`#loadingSpinner` 应在页面加载期间显示，数据请求成功后隐藏。
    3.  **数据展示**：`#approvalListTable` 表格有数据行显示。`#pagination` 分页组件显示的“共X条”总数 > 0。
    4.  **数据格式**：表格中的“时间”列格式符合 `YYYY-MM-DD HH:mm`，“状态”列有对应样式标签。

#### **TC-02: 单个筛选条件查询**
*   **ID:** TC-02
*   **标题:** 使用单个筛选条件进行查询
*   **优先级:** P0
*   **前置条件:** 与TC-01相同。
*   **测试步骤:**
    1.  进入页面，默认数据加载完成。
    2.  **正向用例**：仅修改“时间范围”筛选器（例如选择“最近7天”），保持其他筛选条件为默认值，点击“查询”按钮 (`#searchBtn`)。
    3.  **反向用例**：点击“重置”按钮恢复默认，仅选择“状态”筛选器中的一个状态（如“已通过”），点击“查询”。
*   **预期结果:**
    1.  **操作反馈**：点击查询后，`#loadingSpinner` 应显示，查询按钮 (`#searchBtn`) 状态变为“查询中”或禁用，防止重复提交。
    2.  **数据刷新**：`#loadingSpinner` 消失后，`#approvalListTable` 中的数据列表刷新。
    3.  **结果准确**：
        *   **正向用例**：列表中所有记录的时间均在“最近7天”范围内。
        *   **反向用例**：列表中所有记录的状态均为“已通过”。
    4.  **状态保持**：其他未修改的筛选控件（如“类型”、“发起人”）保持默认值不变。

#### **TC-03: 多条件组合查询**
*   **ID:** TC-03
*   **标题:** 使用多个筛选条件进行组合查询
*   **优先级:** P0
*   **前置条件:** 与TC-01相同。
*   **测试步骤:**
    1.  进入页面。
    2.  同时设置多个筛选条件，例如：时间范围选择“本月”，类型选择“报销审批”，发起人输入“张伟”。
    3.  点击“查询”按钮。
    4.  观察查询结果。
*   **预期结果:**
    1.  **数据一致性**：`#approvalListTable` 中展示的每一条数据必须**同时满足**所有已设置的筛选条件（时间为本月、类型为报销审批、发起人匹配“张伟”）。
    2.  **分页信息**：`#pagination` 中的“共X条”总数应正确反映符合条件的数据条数。

#### **TC-04: 查询无结果时的空状态展示**
*   **ID:** TC-04
*   **标题:** 筛选导致无结果时的空状态展示
*   **优先级:** P0
*   **前置条件:** 与TC-01相同。
*   **测试步骤:**
    1.  进入页面。
    2.  设置一个已知在测试数据中不存在匹配结果的组合筛选条件（例如：时间范围选择“2023-01-01 至 2023-01-02”，同时状态选择“已通过”）。
    3.  点击“查询”按钮。
*   **预期结果:**
    1.  `#loadingSpinner` 正常显示并消失。
    2.  `#approvalListTable` 中无数据行显示。
    3.  页面显示空状态提示区域 (`#emptyState`)，提示信息友好明确（如“暂无数据”）。
    4.  `#pagination` 中“共X条”显示为“共0条”。

#### **TC-05: 重置筛选条件**
*   **ID:** TC-05
*   **标题:** 点击“重置”按钮恢复默认筛选状态
*   **优先级:** P0
*   **前置条件:**
    1.  已执行过TC-02或TC-03，页面处于非默认筛选状态。
*   **测试步骤:**
    1.  确认当前时间范围、状态、类型、发起人搜索框中均有非默认值。
    2.  点击“重置”按钮 (`#resetBtn`)。
*   **预期结果:**
    1.  **控件恢复**：所有筛选控件（`#timeRangeSelector`, `#statusFilter`, `#typeFilter`, `#initiatorSearch`）立即恢复为页面初始加载时的默认值。
    2.  **数据恢复**：`#approvalListTable` 立即刷新，显示的数据与页面首次加载（TC-01）时的数据完全一致。
    3.  **分页恢复**：`#pagination` 页码恢复到第1页，“共X条”总数恢复为初始默认查询的总数。

#### **TC-06: 分页翻页与数据切换**
*   **ID:** TC-06
*   **标题:** 分页组件翻页功能验证
*   **优先级:** P0
*   **前置条件:**
    1.  页面已加载，且`#pagination`显示“共X条”，总数大于一页的数据量（例如，总数>每页条数）。
*   **测试步骤:**
    1.  记录当前第1页的第一条数据的关键信息（如：审批主题）。
    2.  点击“下一页”按钮 (`#pagination .next-page-button`)。
    3.  观察列表数据变化及页码高亮状态。
    4.  点击“上一页”按钮 (`#pagination .prev-page-button`)。
*   **预期结果:**
    1.  **数据切换**：翻页后，表格显示新的数据列表。第2页的第一条数据的关键信息与第1页第一条不同。
    2.  **状态反馈**：翻页过程有加载状态提示。
    3.  **页码状态**：
        *   在第1页时，“上一页”按钮应为禁用 (`disabled`) 状态。
        *   在第2页（中间页）时，“上一页”和“下一页”按钮均为可用状态。
        *   高亮页码从“1”变为“2”。
    4.  点击“上一页”后，页面应准确返回到第1页，且数据与之前记录的第一条数据一致。

#### **TC-07: 列表行“详情”操作**
*   **ID:** TC-07
*   **标题:** 点击列表行“详情”按钮进行跳转
*   **优先级:** P0
*   **前置条件:**
    1.  `#approvalListTable` 中至少存在一条数据。
*   **测试步骤:**
    1.  找到列表中的任意一行数据，记录其“审批主题”和“发起人”信息。
    2.  点击该行操作列的“详情”按钮。
*   **预期结果:**
    1.  **页面跳转**：浏览器发生跳转，新页面的URL中包含当前行的唯一标识（如审批ID，例如：`/approval/detail?id=123`）。
    2.  **数据一致性**：跳转到的详情页面中，展示的“审批主题”、“发起人”等核心摘要信息与列表页中该行展示的信息**完全一致**。

#### **TC-08: 日期范围筛选-无效输入**
*   **ID:** TC-08
*   **标题:** 日期范围筛选-结束日期早于开始日期
*   **优先级:** P1
*   **前置条件:** 与TC-01相同。
*   **测试步骤:**
    1.  点击“时间范围”选择器，选择“自定义范围”。
    2.  设置开始日期为今天（如2024-11-20），结束日期为昨天（如2024-11-19）。
    3.  尝试点击“查询”按钮。
*   **预期结果:**
    1.  **前端校验**：系统应阻止查询请求。日期选择器或页面出现明确的错误提示，例如“结束日期不能早于开始日期”。
    2.  **数据不变**：`#approvalListTable` 和 `#pagination` 数据不应发生变化。

#### **TC-09: 发起人搜索-模糊匹配与无结果**
*   **ID:** TC-09
*   **标题:** 发起人搜索框的模糊搜索与无匹配结果
*   **优先级:** P1
*   **前置条件:** 测试数据中存在“张伟”、“张伟明”、“王伟”发起的记录。
*   **测试步骤:**
    1.  在“发起人”搜索框中输入“张”。
    2.  观察输入框下方是否出现联想列表（如有此设计）。
    3.  在搜索框中输入“不存在的人名-XYZ”，然后点击查询。
*   **预期结果:**
    1.  **模糊匹配**：若存在联想功能，列表应显示包含“张”的所有候选人（如“张伟”、“张伟明”）。若无联想，点击查询后，列表应显示所有发起人包含“张”的记录。
    2.  **无结果查询**：输入“不存在的人名-XYZ”后点击查询，页面应进入空状态（参考TC-04的预期结果）。

#### **TC-10: 分页跳转与每页条数切换**
*   **ID:** TC-10
*   **标题:** 分页组件页码跳转与每页条数切换
*   **优先级:** P1
*   **前置条件:** 数据总数足够，例如“共120条”，默认每页10条。
*   **测试步骤:**
    1.  **页码跳转**：在分页组件的页码输入框中，输入一个有效页码（如“12”），点击跳转按钮或按回车。
    2.  **无效跳转**：输入非数字（如“abc”）或超出范围的页码（如“13”），观察系统反应。
    3.  **切换每页条数**：在“每页条数”下拉框中，选择“20条/页”。
*   **预期结果:**
    1.  **有效跳转**：列表数据立即刷新，显示第12页的数据（共12条），页码高亮显示为“12”。
    2.  **无效跳转**：
        *   输入非数字：系统应不响应或提示输入无效。
        *   输入超出范围的页码（13）：系统应不响应或提示“页码不存在”，列表停留在最后一页（第12页）。
    3.  **切换条数**：切换为20条/页后，列表刷新，每页显示20条数据，分页总页数重新计算并显示（如“共6页”），页码可能跳回第1页。

#### **TC-11: 列表数据导出**
*   **ID:** TC-11
*   **标题:** 验证导出功能的数据一致性
*   **优先级:** P1
*   **前置条件:** 页面有数据，且设置了特定筛选条件（如“时间：最近7天”，“状态：已通过”）。
*   **测试步骤:**
    1.  设置好上述筛选条件并执行查询。
    2.  记录当前列表显示的数据条数（如“共15条”）和第一条数据的关键信息。
    3.  点击“导出”按钮。
    4.  下载生成的文件（如Excel或CSV）。
    5.  打开文件进行检查。
*   **预期结果:**
    1.  **下载触发**：浏览器正常触发文件下载。
    2.  **文件内容**：
        *   文件中的数据条数与页面记录的条数（15条）完全一致。
        *   文件的第一行数据（表头）与页面表格列头一致。
        *   文件的第一条数据内容（如审批主题、发起人、状态）与页面记录的第一条数据**完全一致**。
        *   所有数据均满足“最近7天”和“已通过”的筛选条件。

#### **TC-12: 网络异常时的用户提示**
*   **ID:** TC-12
*   **标题:** 模拟网络异常下的错误提示
*   **优先级:** P2
*   **前置条件:** 具备模拟网络故障的工具（如Chrome DevTools）。
*   **测试步骤:**
    1.  打开Chrome DevTools，进入Network面板。
    2.  将网络状态设置为“Offline”或模拟“超时”。
    3.  在审批历史页面，修改一个筛选条件并点击“查询”。
*   **预期结果:**
    1.  **错误提示**：`#loadingSpinner` 在超时后消失。页面上（如顶部或查询按钮附近）应出现友好的错误提示，例如“网络请求失败，请稍后重试”。
    2.  **页面状态**：页面不应白屏、崩溃或无任何响应。`#approvalListTable` 可保持上次成功加载的数据或显示空状态，但需有明确错误提示覆盖。
    3.  **可恢复性**：恢复网络后，重新点击“查询”按钮应能正常发起请求并更新数据。
