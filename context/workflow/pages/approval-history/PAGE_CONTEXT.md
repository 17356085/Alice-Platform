# 审批历史页面 (`approval-history`) 测试设计

## 1. 页面功能分解与测试焦点

基于提供的页面上下文 (`PAGE_CONTEXT.md`)，该审批历史页面核心是一个**数据驱动的列表查询与管理界面**。测试将聚焦于用户输入（筛选）与系统输出（数据展示、操作反馈）之间的交互准确性、稳定性及用户体验。

**主要测试焦点：**
*   **筛选逻辑的准确性**：单个及组合条件的筛选结果必须符合预期。
*   **数据展示的完整性与一致性**：列表数据、格式、分页信息需与后端数据源保持一致。
*   **用户操作的可预期反馈**：查询、重置、翻页、导出等操作需有明确、及时的状态反馈（加载、成功、错误）。
*   **系统的健壮性**：对非法输入、极端数据、网络异常等情况的防御与友好提示。

## 2. 测试场景设计

测试场景按功能模块组织，旨在覆盖正常流程、异常流程及边界条件。

### 2.1 场景组一：页面初始状态与基本交互
*   **场景 S-01**：首次访问页面，验证默认加载状态。
*   **场景 S-02**：操作所有筛选控件（时间、状态、类型、发起人）但不提交，验证控件自身交互是否正常（如下拉框展开、日期选择器弹出、联想列表显示）。
*   **场景 S-03**：点击“查询”按钮，验证加载状态 (`#loadingSpinner`) 的显示与隐藏，以及查询按钮 (`#searchBtn`) 的防重复点击（如loading时禁用）。
*   **场景 S-04**：点击“重置”按钮，验证所有筛选控件恢复默认值，列表恢复初始状态。

### 2.2 场景组二：筛选查询功能验证
*   **场景 S-05**：时间范围-快捷选项筛选（如“最近7天”、“本月”）。
*   **场景 S-06**：时间范围-自定义日期范围筛选（包含有效范围、跨月、跨年范围）。
*   **场景 S-07**：时间范围-无效/边界日期输入（结束日期早于开始日期、选择遥远未来日期）。
*   **场景 S-08**：状态多选筛选（选择单个、多个状态组合）。
*   **场景 S-09**：类型单选筛选。
*   **场景 S-10**：发起人搜索-输入匹配、部分匹配、无匹配、特殊字符。
*   **场景 S-11**：组合筛选-两个及以上条件同时生效（时间+状态、时间+类型+发起人等）。
*   **场景 S-12**：组合筛选-导致“无结果”的特定组合。

### 2.3 场景组三：数据展示与分页验证
*   **场景 S-13**：列表有数据时，验证表头列名、数据格式（特别是时间格式 `YYYY-MM-DD HH:mm`）、状态标签样式。
*   **场景 S-14**：列表为空时（初始无数据或查询无结果），验证空状态 (`#emptyState`) 显示。
*   **场景 S-15**：分页组件-翻页（上一页、下一页），验证数据切换与页码高亮。
*   **场景 S-16**：分页组件-页码跳转（输入有效页码、无效页码如非数字、超出范围的页码）。
*   **场景 S-17**：分页组件-总数显示（“共X条”）与“每页条数”切换。
*   **场景 S-18**：在列表仅有1页数据时，验证“上一页”、“下一页”按钮为禁用状态。

### 2.4 场景组四：行操作功能验证
*   **场景 S-19**：点击操作列的“详情”按钮，验证页面跳转及详情页数据一致性。
*   **场景 S-20**：点击“导出”按钮，验证文件下载触发及文件内容与当前视图数据（含筛选、分页）一致。

### 2.5 场景组五：异常与健壮性测试
*   **场景 S-21**：模拟慢速网络，验证查询过程中的加载状态提示 (`#loadingSpinner`)。
*   **场景 S-22**：模拟网络断开（Offline）或接口超时，验证错误提示是否友好，页面是否可恢复。
*   **场景 S-23**：在发起人搜索框等输入框注入潜在危险字符（如 `<script>...`），验证是否存在XSS漏洞。
*   **场景 S-24**：模拟后端接口返回异常数据（如字段缺失、数据类型错误），验证前端是否崩溃或能容错展示。

## 3. 测试数据设计要点

测试数据是驱动上述场景的核心，需在测试环境数据库中提前准备。

1.  **基础数据池**：构造不少于100条审批记录。
2.  **状态覆盖**：确保“待审批”、“审批中”、“已通过”、“已驳回”四种状态各有充足数据（每种 > 20条）。
3.  **时间分布**：
    *   **近期**：今天、昨天、最近3天内、最近7天内。
    *   **中期**：本周、上周、最近30天内。
    *   **远期**：3个月前、6个月前、跨年的记录（用于测试时间筛选的远期性能）。
4.  **发起人设计**：
    *   设置多个发起人，其中“张伟”有10条记录。
    *   设置“张伟明”有5条记录（测试模糊搜索的精确匹配）。
    *   设置“王伟”有1条记录（测试筛选后可能变为空列表）。
    *   设置一个仅在远期有记录的发起人。
5.  **类型设计**：覆盖“请假审批”、“报销审批”、“采购审批”等所有业务类型，其中“请假审批”和“报销审批”应占主要比例。
6.  **组合数据**：手动设计几条“高价值”记录，例如：
    *   由“张伟”在“2024-01-15 10:30”发起的、状态为“已通过”的“报销审批”。
    *   由“李雷”在“今天”发起的、状态为“审批中”的“请假审批”。
    *   用于验证特定筛选条件下的唯一性或定位。

## 4. 关键验证点与自动化检查清单

以下为测试执行时需严格核查的验证点，可作为手工测试检查表或自动化断言的依据。

*   **[V-01] 页面加载完整性**：页面无JS错误，所有元素（`#timeRangeSelector`, `#statusFilter`, `#typeFilter`, `#initiatorSearch`, `#searchBtn`, `#resetBtn`, `#approvalListTable`, `#pagination`）均可见且处于默认状态。
*   **[V-02] 默认数据加载**：`#loadingSpinner` 消失后，`#approvalListTable` 显示数据。`#pagination` 中的“共X条”数字 > 0。
*   **[V-03] 单个筛选条件生效**：仅修改一个筛选条件（如时间范围）并点击查询，列表数据**仅**随该条件变化。其他筛选控件保持原值。
*   **[V-04] 组合筛选条件生效**：多个筛选条件组合查询，列表中每条数据必须**同时满足**所有已设置的筛选条件。
*   **[V-05] 查询无结果**：当筛选条件导致无匹配数据时，`#emptyState` 可见，`#approvalListTable` 无数据行，`#pagination` 显示“共0条”。
*   **[V-06] 重置功能**：点击重置后，所有筛选控件恢复为页面初始默认值，列表恢复为初始加载的数据。
*   **[V-07] 分页数据一致性**：翻页后，新页数据与前一页数据不重复（摘要等关键字段不相同）。页码指示器高亮正确。
*   **[V-08] 分页边界状态**：在首页时，“上一页”按钮禁用；在末页时，“下一页”按钮禁用。
*   **[V-09] 操作反馈及时性**：点击查询、重置后，应在300ms内有视觉反馈（按钮loading状态或列表开始刷新）。
*   **[V-10] 导出数据一致性**：导出的Excel/CSV文件内容（列数、行数、数据值）必须与当前页面`#approvalListTable`中显示的数据（在应用当前筛选和分页条件下）完全一致。
*   **[V-11] 详情跳转正确性**：从列表行点击“详情”后，跳转到的目标页面URL包含正确的审批ID，且详情页展示的信息与列表行摘要匹配。
*   **[V-12] 网络异常处理**：在接口请求失败时，页面不应显示为白屏或无响应，应出现友好的错误提示，并允许用户重试查询。

    *   **P1 (重要)**：S-04, S-09, S-10, S-16, S-17, S-20, S-22。 (重要筛选逻辑、分页、操作、关键异常)
