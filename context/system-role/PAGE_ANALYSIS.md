# 测试设计：用户管理列表页

## 1. 页面结构分析

本页面是一个典型的数据列表管理页，主要由以下几部分组成：

1.  **搜索/筛选栏 (Search/Filter Area)**
    -   **输入框 (Input)**：用户名、邮箱
    -   **下拉选择器 (Select)**：用户状态（全部/启用/禁用）
    -   **按钮 (Button)**：搜索、重置

2.  **数据操作栏 (Action Bar)**
    -   **按钮 (Button)**：新增用户（导航）、批量启用、批量禁用
    -   **复选框 (Checkbox)**：表头全选复选框

3.  **数据表格 (Data Table)**
    -   **列 (Column)**： 用户名、邮箱、手机号、状态（显示为Tag/Badge）、创建时间、最后登录时间、操作
    -   **行 (Row)**： 每行代表一条用户数据记录，行前有Checkbox
    -   **操作列 (Actions Column)**： 编辑（图标/文字链接）、启用/禁用（开关/按钮）、删除（图标/文字链接）

4.  **分页控件 (Pagination)**
    -   **控件 (Widget)**： 每页条数选择、页码切换、上一页/下一页、总条数统计

## 2. 可测试元素识别

-   **输入控件**：[x] Input (用户名, 邮箱) [x] Select (状态) [x] Checkbox (行选择, 全选)
-   **触发控件**：[x] Button (搜索, 重置, 新增, 批量操作, 编辑, 启用/禁用, 删除)
-   **展示控件**：[x] Table [x] Tag/Badge (状态) [x] Pagination
-   **交互控件**：[x] Modal/Dialog (删除确认, 批量操作确认) [x] Message/Notification (操作反馈)

## 3. 测试策略与数据设计

### 3.1 核心流程测试 (E2E)

基于用户主要操作路径，设计如下测试场景：

-   **场景 A：默认加载与浏览**
    -   **测试数据**：数据库内至少 25 条数据。
    -   **验证点**：
        1.  请求 URL 正确，页面完全加载无网络错误。
        2.  表格默认渲染 10 条记录。
        3.  分页组件显示 “共 25 条”，可正确点击第 2 页、第 3 页。
        4.  支持切换“每页显示 20 条”，表格应显示 20 条数据。

-   **场景 B：搜索与筛选**
    -   **测试数据**：
        -   精确搜索：用户名 = `admin_test`
        -   模糊搜索：邮箱 = `@gmail.com`
        -   组合搜索：状态 = “禁用” AND 用户名 = `test_1`
        -   无结果搜索：用户名 = `__nonexistent_user__`
    -   **验证点**：
        1.  精确匹配结果唯一。
        2.  模糊匹配返回所有符合条件的结果。
        3.  组合筛选结果符合所有条件。
        4.  无结果时表格显示“暂无数据”，分页隐藏或显示为0条。

-   **场景 C：表格行操作**
    -   **单行操作**：
        -   **启用/禁用**：点击一个“启用”状态用户的“禁用”按钮。验证状态切换为“禁用”，并显示成功提示。
        -   **删除**：点击“删除”按钮，在弹出的 Modal 中点击“取消”（验证不删除），再次点击“删除” -> “确定”。验证页面刷新后该用户记录消失。
    -   **操作按钮状态**：
        1.  某些用户状态下，操作按钮是否可用？例如：已删除用户应看不到“删除”按钮。

-   **场景 D：批量操作**
    -   **测试数据**：
        -   全选所有数据（多页）。
        -   选中部分数据 (n=1, n=2, n=N-1)。
        -   混选（包含已禁用和已启用的用户）。
    -   **验证点**：
        1.  点击“批量禁用”后，弹出确认框，描述操作影响（例如 “确定禁用选中的 3 个用户？”）。
        2.  确认后，所有选中用户的状态变更为“禁用”。
        3.  批量操作结束后，列表数据自动刷新，复选框清空。
        4.  UI 上显示操作成功/失败的反馈（如 Message）。

### 3.2 边界与异常测试

-   **输入框**：
    -   超长输入 (Input maxLength 或超过数据库字段长度)。
    -   输入 SQL 或 XSS 脚本（验证是否被转义）。
-   **选择器**：选择“全部”状态；切换状态选项后重置。
-   **分页**：
    -   只有 1 条数据时，分页如何显示？
    -   数据量为 0 时，页面显示“暂无数据”。
    -   快速连续点击下一页。
-   **删除/批量操作**：
    -   网络请求失败时（模拟 `500` 或超时），页面是否报错，数据是否回滚？是否有重试提示？
    -   删除操作中途浏览器关闭/刷新。

### 3.3 状态与过渡测试

-   **加载状态**：进行搜索、分页切换、删除等操作时，表格区域是否显示“加载中 (Spinner / Skeleton)”？
-   **空状态**：当搜索结果为空时，表格是否友好地展示 `Empty` 组件？操作栏的“批量操作”按钮是否禁用？
-   **错误状态**：接口返回业务错误（如“该用户不允许被禁用”），页面是否正确展示错误信息？

## 4. 关键验证点总结 (Checklist)

-   [ ] **CRUD 操作闭环**：新增 -> 列表展示 -> 编辑 -> 列表更新 -> 删除 -> 列表不再展示。
-   [ ] **搜索筛选项联动**：表单重置后，数据恢复为默认（无筛选条件）的列表状态。
-   [ ] **分页保持**：切换页码/每页条数后，URL (query string)或组件内部状态是否同步？切换为非第一页后，是否回到第一页？
-   [ ] **权限控制 (如适用)**：无“删除”权限的用户，看不到删除按钮。
-   [ ] **数据一致性**：操作失败时，页面数据回滚；操作成功后，前端数据与后端数据完全一致（如状态值）。
-   [ ] **性能**：快速切换页面或搜索时，不发生重复请求或数据错乱。
